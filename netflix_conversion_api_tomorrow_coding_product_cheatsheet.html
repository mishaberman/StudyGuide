Clarifying questions — Coding

  • What does “correct” mean here: accepted events, conversion match rate, no data loss, or API success?
  • Is the failure new, intermittent, partner-specific, campaign-specific, or global?
  • What time window should I inspect?
  • Are these artifacts sanitized? Which fields should I avoid printing?
  • Should I optimize for finding root cause or producing a reusable validation script?
  • Do we have schema docs or known expected examples?

Hypothesis ladder

  1. Input issue: missing fields, bad enum, malformed JSON, wrong types.
  2. Identity/normalization: hashing, case, whitespace, consent, identifier presence.
  3. Mapping: partner ID, campaign ID, pixel/dataset ID, event name.
  4. Temporal: event_time, timezone, delayed ingestion, attribution window.
  5. Transport: rate limits, retries, network, endpoint, auth.
  6. Platform: outage, deployment, dependency, schema rollout.

Python: load JSON/JSONL/CSV safely

import json, csv, pathlib
from collections import Counter, defaultdict
from datetime import datetime, timezone

SENSITIVE = {"email", "phone", "ip", "device_id", "user_id", "idfa", "aaid", "access_token"}

def redact_value(v):
    if v is None: return None
    s = str(v)
    if len(s) <= 6: return "***"
    return s[:2] + "***" + s[-2:]

def redact(obj):
    if isinstance(obj, dict):
        return {k: (redact_value(v) if k.lower() in SENSITIVE else redact(v)) for k, v in obj.items()}
    if isinstance(obj, list):
        return [redact(x) for x in obj]
    return obj

def load_artifact(path):
    p = pathlib.Path(path)
    text = p.read_text(encoding="utf-8").strip()
    if p.suffix.lower() == ".csv":
        with p.open(newline="", encoding="utf-8") as f:
            return list(csv.DictReader(f))
    if p.suffix.lower() == ".jsonl":
        return [json.loads(line) for line in text.splitlines() if line.strip()]
    if p.suffix.lower() == ".json":
        data = json.loads(text)
        return data if isinstance(data, list) else [data]
    raise ValueError(f"Unsupported file type: {p.suffix}")

Python: group failures and find blast radius

def get(d, path, default=None):
    cur = d
    for key in path.split("."):
        if not isinstance(cur, dict) or key not in cur:
            return default
        cur = cur[key]
    return cur

def summarize(records):
    by_status = Counter(get(r, "response.status", get(r, "status", "unknown")) for r in records)
    by_error = Counter(get(r, "response.error.code", get(r, "error_code", "none")) for r in records)
    by_partner = Counter(get(r, "partner_id", get(r, "request.partner_id", "unknown")) for r in records)
    return {"total": len(records), "by_status": by_status, "by_error": by_error, "by_partner": by_partner}

def blast_radius(records):
    failed = [r for r in records if str(get(r,"response.status",get(r,"status",""))).startswith(("4","5"))]
    return {
      "failed_count": len(failed),
      "failure_rate": round(len(failed)/max(len(records),1)*100,2),
      "partners_impacted": len(set(get(r,"partner_id","unknown") for r in failed)),
      "top_errors": Counter(get(r,"response.error.code","none") for r in failed).most_common(5)
    }

Python: schema-ish validator for CAPI events

REQUIRED = ["event_name", "event_time", "partner_id"]
ALLOWED_EVENTS = {"Purchase", "Lead", "Subscribe", "AddToCart", "Signup", "ViewContent"}

def validate_event(event):
    errors = []
    for f in REQUIRED:
        if event.get(f) in (None, "", []):
            errors.append(f"missing:{f}")
    if event.get("event_name") and event["event_name"] not in ALLOWED_EVENTS:
        errors.append("bad_enum:event_name")
    if "event_time" in event:
        try:
            ts = int(event["event_time"])
            if ts < 946684800 or ts > 4102444800:
                errors.append("suspicious:event_time")
        except Exception:
            errors.append("bad_type:event_time")
    ids = event.get("user_data", {})
    if not any(ids.get(k) for k in ["email_sha256", "phone_sha256", "external_id", "device_id"]):
        errors.append("missing:user_identifier")
    if event.get("consent") is False:
        errors.append("blocked:consent_false")
    return errors

def validation_report(events):
    counts = Counter()
    examples = defaultdict(list)
    for e in events:
        for err in validate_event(e.get("request", e)):
            counts[err] += 1
            if len(examples[err]) < 3:
                examples[err].append(redact(e))
    return counts, examples

Python: compare success vs failure payloads

def flatten(d, prefix=""):
    out = {}
    if isinstance(d, dict):
        for k, v in d.items():
            out.update(flatten(v, f"{prefix}.{k}" if prefix else k))
    else:
        out[prefix] = type(d).__name__
    return out

def compare_shapes(success_records, failed_records):
    success_keys = Counter()
    failed_keys = Counter()
    for r in success_records:
        success_keys.update(flatten(r.get("request", r)).keys())
    for r in failed_records:
        failed_keys.update(flatten(r.get("request", r)).keys())
    only_fail = sorted(set(failed_keys) - set(success_keys))
    missing_in_fail = sorted(set(success_keys) - set(failed_keys))
    rare_in_fail = [k for k,c in failed_keys.items() if c < max(2, len(failed_records)*0.05)]
    return {"missing_in_fail": missing_in_fail[:25], "only_in_fail": only_fail[:25], "rare_in_fail": rare_in_fail[:25]}

SQL: failure rate + blast radius

-- Replace table/columns with provided artifact schema.
SELECT
  partner_id,
  DATE_TRUNC('hour', request_ts) AS hr,
  COUNT(*) AS total_requests,
  SUM(CASE WHEN status_code >= 400 THEN 1 ELSE 0 END) AS failed_requests,
  ROUND(100.0 * SUM(CASE WHEN status_code >= 400 THEN 1 ELSE 0 END) / COUNT(*), 2) AS failure_pct,
  COUNT(DISTINCT campaign_id) AS campaigns_seen,
  COUNT(DISTINCT error_code) AS error_types
FROM capi_request_logs
WHERE request_ts >= CURRENT_TIMESTAMP - INTERVAL '24 hours'
GROUP BY 1,2
ORDER BY failure_pct DESC, failed_requests DESC;

SQL: compare before/after regression

WITH base AS (
  SELECT
    CASE WHEN request_ts < TIMESTAMP '2026-05-19 18:00:00' THEN 'before' ELSE 'after' END AS period,
    error_code,
    status_code,
    COUNT(*) AS n
  FROM capi_request_logs
  WHERE request_ts BETWEEN TIMESTAMP '2026-05-19 12:00:00' AND TIMESTAMP '2026-05-20 00:00:00'
  GROUP BY 1,2,3
)
SELECT period, status_code, error_code, n,
       ROUND(100.0 * n / SUM(n) OVER (PARTITION BY period), 2) AS pct_of_period
FROM base
ORDER BY error_code, period;

Escalation hygiene

FactsCounts, timestamps, status codes, redacted request IDs, affected partner/campaign.
HypothesisWhat likely changed and why it explains the data.
ConfidenceHigh if reproduced + clustered; medium if correlated; low if sparse.
RiskData loss, delayed reporting, incorrect attribution, privacy exposure, launch blocker.
ActionFix, rollback, retry, replay, rate-limit, monitor, partner update.

Final coding script to say out loud

“I’ve tried to avoid overfitting to one example. The repeatable evidence is: failures cluster around __, the successful records differ by __, and the blast radius appears limited to __. I’d package the debug pack with redacted samples, validation counts, the likely root cause, and recommended owner/next action.”

4. Product Thinking Cockpit

This interview is about decision quality under ambiguity: customer needs, technical constraints, partner advocacy, tradeoffs, and long-term impact.

45 min

Framework: PACT-RO

  • Problem + customer
  • Assumptions + unknowns
  • Constraints: privacy, correctness, timeline
  • Tradeoffs
  • Recommendation
  • Operations: metrics, rollback, support

What to optimize

  • Correct event ingestion
  • Partner time-to-launch
  • Advertiser trust
  • Privacy-safe validation
  • Platform scalability
  • Operational simplicity

What not to do

  • Jump to solution before clarifying.
  • Promise a custom one-off without naming cost.
  • Ignore privacy or data retention.
  • Frame partner as “wrong” without evidence.
  • Optimize only for launch date.

Product answer skeleton

First, I’d clarify the goal: are we optimizing launch speed, conversion accuracy, partner adoption, or operational stability? Then I’d identify constraints — privacy, API contract, engineering capacity, and reversibility. My recommendation would be [choice], because [business reason], with [risk controls], [metric], and [rollback].
