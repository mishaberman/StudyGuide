2. Coding / Integration interview operating system

Mindset: This is not LeetCode. It is a hands-on integration investigation. The interviewer wants to watch you clarify, inspect artifacts, write pragmatic scripts, validate hypotheses, protect sensitive data, and communicate a debug pack.

Clarify

  • What is failing?
  • Expected vs actual?
  • Which partner / endpoint / time window?
  • What output do they want?
  • Any sensitive fields?

Inspect

  • Sample shape
  • Parse errors
  • Status distribution
  • Error code taxonomy
  • Success vs failure examples

Prove

  • Quantify impact
  • Find smallest explaining difference
  • Segment blast radius
  • State confidence + caveats
  • Give next action

The “CAPI 12” root-cause map

1. Auth

Expired token, wrong scope, wrong partner account, clock skew.

2. Routing

Wrong partner_id, advertiser_id, dataset_id, pixel_id, endpoint.

3. Schema

Missing fields, renamed nested keys, wrong version, bad enum.

4. Types

String vs number, epoch ms vs seconds, booleans as strings.

5. Identity

Hashing, normalization, click IDs, external IDs, IP+UA.

6. Consent

Denied/unknown consent, region suppression, privacy flags.

7. Dedupe

Unstable event_id, retry duplication, idempotency missing.

8. Freshness

Late events, future events, timezone, ETL lag, reporting SLA.

9. Transform

ETL drops nulls, truncates fields, changes casing, maps wrong enum.

10. Rate/Retry

429, backoff, batch size, retries storm, partial failures.

11. Downstream

Accepted but not visible, reporting job lag, activation pipeline.

12. Observability

Error too vague, missing request_id, no partner-level dashboard.

4. Mock CAPI artifact cases

Open each case and practice saying the investigation plan out loud before reading the likely answer.

Case 1: 400 spike after launchPartner A reports a sudden 400 spike on /v1/conversions after enabling schema v3.

Artifacts

Requests, responses, and 50 NDJSON logs. Failing payloads use event_time=1779230400000 and user.email instead of user_data.em.

What to check

  • Group by schema_version and error_code
  • Compare success vs failure keys
  • Check timestamp seconds vs milliseconds
  • Check renamed/missing user_data fields
  • Quantify start time and blast radius

Likely answer

Schema drift plus timestamp unit mismatch. Recommend partner payload fix, clearer validation message, and schema contract test.

Case 2: Duplicate purchasesAdvertiser sees duplicate Purchase conversions after intermittent 5xx errors.

Artifacts

Retries show order_id is stable but event_id is regenerated on every retry.

What to check

  • Group attempts by order_id
  • Check event_id stability across retries
  • Inspect retry status sequence
  • Check idempotency/dedupe behavior
  • Estimate duplicate count and affected revenue reporting

Likely answer

Retry client regenerates event_id, defeating dedupe. Recommend stable event_id derived from conversion/order ID and idempotency tests.

Case 3: Accepted events but low match ratePartner sees 202 Accepted, but matchability/activation quality is poor.

Artifacts

Payloads have no click IDs, no IP+UA, emails are uppercase unhashed in some samples, consent flags inconsistent.

What to check

  • Measure identifier coverage
  • Validate SHA-256 hash format
  • Check normalization lowercase/trim
  • Check consent suppression
  • Segment by event_source/action_source

Likely answer

Payload quality issue, not availability issue. Recommend normalization/hashing fix, richer match keys where allowed, and quality dashboard.

Case 4: Audience onboarding mismatchPartner uploaded 1M audience records, but activated audience is far smaller than expected.

Artifacts

CSV/ETL sample has blank external_id, inconsistent country codes, and phone hashes produced before E.164 normalization.

What to check

  • Null/empty rate by identifier
  • Deduplicate source rows
  • Normalize country/phone/email before hashing
  • Check consent/region filtering
  • Validate ETL row counts at every stage

Likely answer

Data preparation and normalization issue. Recommend preflight validator and row-count reconciliation by stage.

Case 5: Reporting delay vs ingestion failurePartner says events are missing from campaign reporting.

Artifacts

Ingestion accepted events; downstream reporting job has 6-hour freshness lag for one region.

What to check

  • Separate ingestion, processing, and reporting layers
  • Check freshness SLA by region
  • Correlate event IDs downstream
  • Look for backfill/replay status
  • Communicate accurate layer of failure

Likely answer

Downstream freshness delay, not API rejection. Recommend partner comms, backlog monitoring, and alert on freshness lag.

Case 6: Privacy suppression surprisePartner expects all events to count, but many are suppressed.

Artifacts

Events from certain regions include consent='denied' but partner expected them to be measured.

What to check

  • Group suppression by consent/region/action_source
  • Validate policy behavior
  • Check partner docs and implementation
  • Never suggest bypassing privacy
  • Quantify eligible vs ineligible

Likely answer

Integration is behaving correctly per privacy policy; partner expectation/docs need alignment. Recommend doc clarification and dashboard.

Script 1

Python: ingest JSON/NDJSON artifacts + summarize failure patterns

Use first when they give sample request/response/log artifacts. Shows robustness, grouping, and privacy-safe output.

#!/usr/bin/env python3
"""
Goal: Load mixed JSON / NDJSON artifacts, redact sensitive fields, and summarize integration failures.
Use in CodeSignal when you receive sample requests, responses, or logs.
"""
import json, sys, re, statistics
from collections import Counter, defaultdict
from pathlib import Path

SENSITIVE_KEYS = {"email", "phone", "ip", "ip_address", "client_ip_address", "user_agent", "em", "ph", "external_id", "first_name", "last_name"}
EMAIL_RE = re.compile(r"[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}")

def redact(obj):
    if isinstance(obj, dict):
        out = {}
        for k, v in obj.items():
            if k.lower() in SENSITIVE_KEYS:
                out[k] = "<REDACTED>"
            else:
                out[k] = redact(v)
        return out
    if isinstance(obj, list):
        return [redact(x) for x in obj]
    if isinstance(obj, str):
        return EMAIL_RE.sub("<EMAIL_REDACTED>", obj)
    return obj

def load_records(path):
    text = Path(path).read_text().strip()
    if not text:
        return []
    try:
        parsed = json.loads(text)
        return parsed if isinstance(parsed, list) else [parsed]
    except json.JSONDecodeError:
        rows = []
        for i, line in enumerate(text.splitlines(), 1):
            line = line.strip()
            if not line:
                continue
            try:
                rows.append(json.loads(line))
            except json.JSONDecodeError as e:
                rows.append({"_parse_error": str(e), "_line": i, "raw": line[:300]})
        return rows

def get(d, path, default=None):
    cur = d
    for part in path.split("."):
        if not isinstance(cur, dict) or part not in cur:
            return default
        cur = cur[part]
    return cur

def classify(record):
    status = record.get("status") or get(record, "response.status") or get(record, "http.status") or "unknown"
    endpoint = record.get("endpoint") or get(record, "request.endpoint") or get(record, "request.path") or "unknown"
    error = record.get("error_code") or get(record, "response.error.code") or get(record, "error.code") or "none"
    partner = record.get("partner_id") or get(record, "request.partner_id") or get(record, "payload.partner_id") or "unknown"
    schema = record.get("schema_version") or get(record, "payload.schema_version") or "unknown"
    return str(status), str(endpoint), str(error), str(partner), str(schema)

def main(paths):
    records = []
    for p in paths:
        records.extend(load_records(p))

    by_status = Counter()
    by_error = Counter()
    by_endpoint = Counter()
    by_partner_error = Counter()
    parse_errors = []

    for r in records:
        if "_parse_error" in r:
            parse_errors.append(r)
            continue
        status, endpoint, error, partner, schema = classify(r)
        by_status[status] += 1
        by_endpoint[endpoint] += 1
        by_error[error] += 1
        by_partner_error[(partner, error)] += 1

    print("=== SUMMARY ===")
    print("records:", len(records), "parse_errors:", len(parse_errors))
    print("status:", by_status.most_common())
    print("errors:", by_error.most_common(10))
    print("endpoints:", by_endpoint.most_common(10))
    print("partner+error:", by_partner_error.most_common(10))

    print("\n=== SAFE SAMPLE RECORDS ===")
    for r in records[:3]:
        print(json.dumps(redact(r), indent=2)[:1500])

if __name__ == "__main__":
    if len(sys.argv) < 2:
        print("Usage: python analyze_artifacts.py artifact1.json [artifact2.ndjson ...]")
        sys.exit(1)
    main(sys.argv[1:])
Script 2

Python: CAPI payload validator with root-cause hints

Checks the kinds of payload issues common in conversion APIs: required fields, timestamps, dedupe IDs, user identifiers, privacy flags, purchase fields.

import json, re, time, hashlib
from collections import Counter, defaultdict

SHA256_RE = re.compile(r"^[a-f0-9]{64}$")
EMAIL_RE = re.compile(r"^[^@\s]+@[^@\s]+\.[^@\s]+$")
REQUIRED = ["event_name", "event_time", "event_id", "action_source", "partner_id"]

PURCHASE_REQUIRED = ["custom_data.value", "custom_data.currency"]

def nested_get(d, path):
    cur = d
    for p in path.split("."):
        if not isinstance(cur, dict) or p not in cur:
            return None
        cur = cur[p]
    return cur

def normalized_sha256(value: str) -> str:
    return hashlib.sha256(value.strip().lower().encode("utf-8")).hexdigest()

def validate_event(e, now=None):
    now = now or int(time.time())
    problems = []

    for f in REQUIRED:
        if nested_get(e, f) in (None, "", []):
            problems.append(("missing_required", f, "Required for routing, dedupe, or eligibility."))

    event_time = e.get("event_time")
    if isinstance(event_time, int):
        if event_time > 10_000_000_000:
            problems.append(("timestamp_unit", "event_time", "Looks like milliseconds; most CAPI APIs expect epoch seconds."))
        elif event_time > now + 300:
            problems.append(("timestamp_future", "event_time", "Event time is in the future; check timezone/unit."))
        elif now - event_time > 7 * 24 * 3600:
            problems.append(("timestamp_old", "event_time", "Event may be outside attribution/acceptance window."))
    else:
        problems.append(("timestamp_type", "event_time", "Expected integer epoch seconds."))

    user_data = e.get("user_data") or {}
    if not user_data:
        problems.append(("missing_user_data", "user_data", "Low/no matchability; check identifiers and consent."))
    else:
        em = user_data.get("em") or user_data.get("email")
        if em:
            if EMAIL_RE.match(str(em)):
                problems.append(("plaintext_pii", "user_data.em/email", "Do not log or send plaintext PII if API requires normalized SHA-256."))
            elif not SHA256_RE.match(str(em).lower()):
                problems.append(("bad_hash_format", "user_data.em", "Expected lowercase 64-char SHA-256 hex."))
        if not any(k in user_data for k in ["em", "ph", "external_id", "fbc", "fbp", "gclid", "client_ip_address", "user_agent", "madid"]):
            problems.append(("weak_match_keys", "user_data", "No recognizable match keys; expect poor match rate."))

    if e.get("event_name") == "Purchase":
        for f in PURCHASE_REQUIRED:
            if nested_get(e, f) in (None, ""):
                problems.append(("purchase_missing_field", f, "Purchase event needs value/currency for measurement quality."))

    if e.get("consent") == "denied" and e.get("processing_status") != "suppressed":
        problems.append(("privacy_logic", "consent", "Consent denied events should be suppressed or handled per policy."))

    return problems

def summarize(events):
    counts = Counter()
    examples = defaultdict(list)
    seen_ids = Counter(e.get("event_id") for e in events if e.get("event_id"))
    for e in events:
        for code, field, hint in validate_event(e):
            counts[code] += 1
            if len(examples[code]) < 3:
                examples[code].append({"event_id": e.get("event_id"), "field": field, "hint": hint})
    dups = {eid: c for eid, c in seen_ids.items() if c > 1}
    if dups:
        counts["duplicate_event_id"] = sum(dups.values())
        examples["duplicate_event_id"] = list(dups.items())[:5]
    return counts, examples

# Usage: events = json.load(open('payloads.json')); print(summarize(events))

Python: compare successful vs failing payloads and find likely schema drift

Great when you have a few good and bad sample payloads. It proves differences instead of guessing.

from collections import Counter

def flatten(d, prefix=""):
    out = {}
    if isinstance(d, dict):
        for k, v in d.items():
            out.update(flatten(v, f"{prefix}.{k}" if prefix else k))
    elif isinstance(d, list):
        out[prefix] = "<list>"
    else:
        out[prefix] = type(d).__name__
    return out

def compare_groups(success_payloads, failed_payloads):
    success_keys = Counter()
    failed_keys = Counter()
    success_types = Counter()
    failed_types = Counter()

    for p in success_payloads:
        f = flatten(p)
        success_keys.update(f.keys())
        success_types.update(f.items())
    for p in failed_payloads:
        f = flatten(p)
        failed_keys.update(f.keys())
        failed_types.update(f.items())

    n_success, n_failed = max(1, len(success_payloads)), max(1, len(failed_payloads))
    print("Keys common in success but missing/rare in failures:")
    for key, count in success_keys.most_common():
        s_rate = count / n_success
        f_rate = failed_keys[key] / n_failed
        if s_rate >= 0.8 and f_rate <= 0.2:
            print(f"  {key}: success {s_rate:.0%}, failed {f_rate:.0%}")

    print("\nKeys common in failures but rare in success, possible wrong field name or schema drift:")
    for key, count in failed_keys.most_common():
        f_rate = count / n_failed
        s_rate = success_keys[key] / n_success
        if f_rate >= 0.8 and s_rate <= 0.2:
            print(f"  {key}: failed {f_rate:.0%}, success {s_rate:.0%}")

    print("\nType differences:")
    all_keys = set(success_keys) | set(failed_keys)
    for key in sorted(all_keys):
        st = {t for (k, t), c in success_types.items() if k == key}
        ft = {t for (k, t), c in failed_types.items() if k == key}
        if st and ft and st != ft:
            print(f"  {key}: success types {st}, failed types {ft}")

Python: correlate request/response/log lines by request_id/event_id

Shows integration testing mindset: connect artifacts end-to-end rather than treating each file separately.

import json
from collections import defaultdict

def index_by(records, keys=("request_id", "trace_id", "event_id")):
    idx = defaultdict(list)
    for r in records:
        for k in keys:
            v = r.get(k) or (r.get("payload") or {}).get(k)
            if v:
                idx[(k, v)].append(r)
    return idx

def join_artifacts(requests, responses, logs):
    all_records = [("request", r) for r in requests] + [("response", r) for r in responses] + [("log", r) for r in logs]
    grouped = defaultdict(list)
    for source, record in all_records:
        for key in ["request_id", "trace_id", "event_id"]:
            val = record.get(key) or (record.get("payload") or {}).get(key)
            if val:
                grouped[(key, val)].append((source, record))
                break
    for correlation_key, items in grouped.items():
        sources = {s for s, _ in items}
        if {"request", "response", "log"}.issubset(sources):
            print("complete trace", correlation_key, "items", len(items))
        elif "response" not in sources:
            print("missing response", correlation_key)
        elif "log" not in sources:
            print("missing log", correlation_key)

Script 5

Python: latency, retry, and idempotency checks

Helpful for CAPI incidents where events are duplicated, delayed, or intermittently failing.

from collections import Counter, defaultdict
import statistics

def pct(values, p):
    if not values:
        return None
    values = sorted(values)
    k = int(round((len(values)-1) * p/100))
    return values[k]

def reliability_report(records):
    latencies = [r.get("latency_ms") for r in records if isinstance(r.get("latency_ms"), (int, float))]
    statuses = Counter(r.get("status") for r in records)
    by_event = defaultdict(list)
    for r in records:
        eid = r.get("event_id") or (r.get("payload") or {}).get("event_id")
        if eid:
            by_event[eid].append(r)

    print("status counts", statuses)
    print("latency p50/p95/p99", pct(latencies, 50), pct(latencies, 95), pct(latencies, 99))

    retried = {eid: rows for eid, rows in by_event.items() if len(rows) > 1}
    print("events retried/duplicated", len(retried))
    for eid, rows in list(retried.items())[:10]:
        print(eid, "attempts", len(rows), "statuses", [r.get("status") for r in rows])

    # Red flag: retry creates new event_id, preventing dedupe.
    # Check by order_id or conversion_id if available.
    by_order = defaultdict(set)
    for r in records:
        payload = r.get("payload") or r
        order_id = (payload.get("custom_data") or {}).get("order_id")
        event_id = payload.get("event_id")
        if order_id and event_id:
            by_order[order_id].add(event_id)
    for order_id, event_ids in by_order.items():
        if len(event_ids) > 1:
            print("possible unstable event_id for same order", order_id, event_ids)

SQL: core integration failure dashboard query

Use when they expect SQL validation: status, endpoint, partner, schema, error buckets, time window.

-- Goal: quantify blast radius and isolate strongest dimensions.
SELECT
  date_trunc('hour', received_at) AS hour,
  partner_id,
  endpoint,
  schema_version,
  http_status,
  error_code,
  COUNT(*) AS events,
  COUNT(DISTINCT event_id) AS distinct_events,
  ROUND(100.0 * SUM(CASE WHEN http_status BETWEEN 200 AND 299 THEN 1 ELSE 0 END) / COUNT(*), 2) AS success_rate
FROM capi_ingestion_logs
WHERE received_at >= current_timestamp - INTERVAL '24 hours'
GROUP BY 1,2,3,4,5,6
ORDER BY hour DESC, events DESC;

SQL: compare pre/post deployment or launch window

Shows you think in evidence and timelines, not anecdotes.

WITH labeled AS (
  SELECT
    CASE WHEN received_at < TIMESTAMP '2026-05-19 18:00:00' THEN 'pre' ELSE 'post' END AS window,
    partner_id,
    error_code,
    http_status,
    COUNT(*) AS events
  FROM capi_ingestion_logs
  WHERE received_at BETWEEN TIMESTAMP '2026-05-19 12:00:00' AND TIMESTAMP '2026-05-20 00:00:00'
  GROUP BY 1,2,3,4
)
SELECT
  partner_id,
  error_code,
  http_status,
  SUM(CASE WHEN window='pre' THEN events ELSE 0 END) AS pre_events,
  SUM(CASE WHEN window='post' THEN events ELSE 0 END) AS post_events,
  SUM(CASE WHEN window='post' THEN events ELSE 0 END) - SUM(CASE WHEN window='pre' THEN events ELSE 0 END) AS delta
FROM labeled
GROUP BY 1,2,3
ORDER BY ABS(delta) DESC;

Python: safe redaction utility for debug packs

Directly addresses sensitive data handling. This is a high-signal interview behavior.

import json, re

SENSITIVE_KEY_PATTERNS = [
    re.compile(p, re.I) for p in [
        r"email|^em$|phone|^ph$|ip_address|client_ip|user_agent|external_id|first_name|last_name|address|token|authorization|cookie"
    ]
]
EMAIL_RE = re.compile(r"[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}")
TOKEN_RE = re.compile(r"(Bearer\s+)[A-Za-z0-9._\-]+", re.I)

def is_sensitive_key(key):
    return any(p.search(key) for p in SENSITIVE_KEY_PATTERNS)

def redact_value(value):
    if isinstance(value, str):
        value = EMAIL_RE.sub("<EMAIL_REDACTED>", value)
        value = TOKEN_RE.sub(r"\1<REDACTED_TOKEN>", value)
    return "<REDACTED>" if not isinstance(value, (dict, list)) else redact(value)

def redact(obj):
    if isinstance(obj, dict):
        return {k: (redact_value(v) if is_sensitive_key(k) else redact(v)) for k, v in obj.items()}
    if isinstance(obj, list):
        return [redact(x) for x in obj]
    if isinstance(obj, str):
        return EMAIL_RE.sub("<EMAIL_REDACTED>", TOKEN_RE.sub(r"\1<REDACTED_TOKEN>", obj))
    return obj
